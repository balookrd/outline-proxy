# samsung_tv: токены Samsung по исходящему IP

Дата: 2026-08-09. Область: репозиторий
`~/Yandex.Disk.localized/IdeaProjects/smarthome`, сервис `samsung_tv`;
данные — `198.18.1.125:/mnt/HD/HD_a2/k8s/smarthome/samsung_tv/devices.json`.

## Проблема

Samsung привязывает токен авторизации к клиенту, а клиента различает по IP.
В кластере IP — это адрес ноды (`hostNetwork`), и он меняется при каждом
переезде пода.

Код хранит **один токен на устройство**:

```python
if event == 'ms.channel.connect':
    if data.get('token'):
        device['token'] = data['token']
        await store.save(json.dumps(devices))
```

Поэтому авторизация на второй ноде затирает токен первой. Проверено вживую:
под последовательно стоял на `k3s-1`, `k3s-2`, `k3s-3`, на каждой проходила
авторизация, а после возврата на `k3s-1` телевизор снова потребовал
подтверждение — токен в файле принадлежал уже `k3s-3`.

Симптом в логах — `send_key <ip>: unexpected event ms.channel.timeOut`:
WebSocket соединяется, телевизор показывает запрос на экране, подтверждения нет,
диалог истекает, команда не уходит.

## Решение

Хранить токены словарём по исходящему IP:

```json
{"name": "hall", "ip": "198.18.1.91", "tokens": {"198.18.1.51": "12345678"}}
```

### Определение своего адреса

```python
def local_ip_for(addr: str) -> str | None:
    try:
        with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as s:
            s.connect((addr, 9))
            return s.getsockname()[0]
    except OSError:
        return None
```

UDP-`connect` не отправляет пакетов — он лишь заставляет ядро выбрать маршрут,
после чего `getsockname()` возвращает адрес, который телевизор увидит как
источник.

Адрес вычисляется **на каждый телевизор отдельно**, а не один раз на процесс:
у ноды два интерфейса (`lan0` 10.10.10.0/24 и `wan0` 198.18.1.0/24), и опираться
на «главный» адрес хоста нельзя. Downward API (`status.hostIP`) для этого тоже
не годится — он отдаёт `10.10.10.5x`, то есть адрес интерконнекта, а не тот, с
которого уходит трафик к телевизорам.

### Изменения в `send_key`

Токен читается из `device['tokens'][src_ip]`, новый — туда же и пишется.
Остальное (WebSocket, формат команд, WoL, опрос состояния) не меняется.

Если `local_ip_for` вернул `None` (адрес недостижим), работаем с пустым токеном:
поведение то же, что при отсутствии токена сегодня, — телевизор запросит
авторизацию.

## Миграция — разовая, руками

Текущий токен в `devices.json` действителен для `198.18.1.51`: владелец
авторизовался на `k3s-1` последним, и под сейчас там же.

Конвертация делается **однократной правкой файла на NAS**, а не кодом:

```json
"token": "X"   →   "tokens": {"198.18.1.51": "X"}
```

Автомиграция в коде отвергнута сознательно. Она была бы вынуждена угадывать,
какому IP принадлежит старое поле, по тому, где под оказался при запуске:
сегодня угадала бы верно, а после любого перепланирования записала бы неверное
соответствие — и молча, потому что код считал бы токен существующим. Ошибка
проявилась бы как `ms.channel.timeOut` без единой подсказки о причине.

Поддержки старого формата в коде не остаётся: поле `token` не читается.

## Что это даёт

Под переезжает между нодами свободно. На каждой ноде первая команда телевизору
потребует подтверждения на экране, дальше эта нода помнит свой токен. Для трёх
нод — три авторизации на телевизор, однократно.

Авторизации на `.52` и `.53`, сделанные ранее, потеряны: их токены затёрлись до
появления нового формата. После выката эти две ноды придётся авторизовать
заново.

## Что НЕ входит

- **WoL.** Он с токенами никак не связан: бродкаст на `255.255.255.255:9`
  уходит без всякой авторизации. Отдельно установлено, что magic-пакет с ноды
  `k3s-1` не долетел до `.102`, хотя оба в `198.18.1.0/24` — это самостоятельная
  задача, и она этой правкой не закрывается.
- Изменения в остальных четырёх сервисах: формат `devices.json` у каждого свой.
- Прибивание пода к ноде: смысл правки в том, чтобы этого не требовалось.

## Риски

- **Токен по-прежнему один на пару «ТВ + IP».** Если у ноды сменится адрес
  (переезд DHCP, пересборка), токен для старого адреса станет мусором и молча
  осядет в файле. Некритично, но словарь со временем накопит мёртвые ключи.
- **Разовая правка файла требует, чтобы под в этот момент стоял на `k3s-1`** —
  иначе записанное соответствие окажется ложным. Проверяется перед правкой.
- **`local_ip_for` открывает сокет на каждую команду.** Это дёшево (пакетов
  нет), но добавляет системный вызов в путь отправки; при недоступной сети
  вернёт `None` быстро, без таймаута.
