# Спецификация: Клиент Outline Proxy для Windows (Tauri v2 + Rust)

## 1. Введение и цели

Цель проекта — создать полноценный нативный клиент Outline Proxy для операционной системы Windows (Windows 10 / Windows 11 x86_64), обеспечивающий функциональный паритет с существующим клиентом для macOS ([`macos/README.ru.md`](file:///Users/mvmalykh/IdeaProjects/outline-proxy/macos/README.ru.md)).

Клиент строится по модульной двухпроцессной архитектуре:
1. **Сетевое ядро (`outline-ws-rust.exe`)**: существующий бинарник data plane из монорепозитория, портированный под `x86_64-pc-windows-msvc`. Поддерживает VLESS, Shadowsocks AEAD, WebSocket, HTTP/3, QUIC, пулинг соединений, маскировку под браузеры и обход блокировок.
2. **TUN-драйвер (`wintun.dll`)**: официальная высокопроизводительная библиотека Wintun от команды WireGuard.
3. **GUI-оболочка (`bins/outline-windows`)**: легковесное приложение на Rust (Tauri v2) с интерфейсом на Svelte + Tailwind CSS + TypeScript, живущее в системном трее Windows.

Тестовая среда и отладка: виртуальная машина Windows 10/11 x86_64 на NAS `.105` (UGREEN), доступная с хост-системы macOS по RDP.

## 3. Компоненты и технические требования

### 3.1. Адаптация сетевого ядра (`bins/outline-ws-rust`) под Windows

1. **Аллокатор памяти**:
   - `tikv-jemallocator` отключается на платформе Windows (`#[cfg(not(windows))]`).
   - На Windows по умолчанию активируется `mimalloc` (крейт `mimalloc`, уже присутствующий в `Cargo.toml` как альтернативный аллокатор). Фоновый сборщик `spawn_mimalloc_maintenance()` обеспечивает периодический возврат памяти операционной системе.
2. **Изоляция платформозависимого кода**:
   - Дескрипторы `std::os::fd::RawFd` в `bins/outline-ws-rust/src/lib.rs` и сигналы `tokio::signal::unix` закрываются макросом `#[cfg(unix)]`. Для Windows используется `tokio::signal::ctrl_c()`.
   - В `crates/outline-net/src/lib.rs`: исключаются специфичные для Linux вызовы `setsockopt` (`SO_MARK`, `IPV6_PREFER_SRC_PUBLIC`, `IPV6_FREEBIND`).
   - В `crates/outline-transport/src/carrier_loss.rs`: опрос `TCP_INFO` изолируется макросом `#[cfg(target_os = "linux")]`, на Windows метрика отдаёт безопасное значение по умолчанию.
   - В `crates/outline-transport/src/fingerprint_profile.rs`: вызов `libc::gethostname` заменяется на безопасное чтение переменной окружения `COMPUTERNAME` или `GetComputerNameW`.
   - В `crates/outline-uplink/src/manager/reselect.rs`: функция `libc::localtime_r` заменяется на `localtime_s` под Windows.

### 3.2. Бэкенд Wintun в `crates/outline-tun`

1. **Интеграция драйвера Wintun**:
   - Подключение крейта `wintun` (динамическая загрузка `wintun.dll` в рантайме).
   - Реализация интерфейса устройства `open_wintun_device(config: &TunConfig)`:
     - Создание адаптера с именем (по умолчанию `OutlineProxy`, GUID фиксирован для предотвращения дубликатов).
     - Инициализация сессии Wintun с кольцевым буфером пакетов (ring capacity 4–8 МиБ).
     - Запуск асинхронного воркера (Tokio task / worker thread), читающего пакеты из сессии Wintun через `receive_packet()` и Win32 Event handle, передающего их в движок TUN.
     - Запись исходящих пакетов из TUN writer в Wintun через `allocate_send_packet()` и `send_packet()`.
2. **Управление сетевыми маршрутами и шлюзом**:
   - При старте TUN:
     - Определение текущего шлюза по умолчанию (default gateway) и физического сетевого интерфейса через Win32 `GetBestRoute2` / `GetAdaptersAddresses`.
     - Добавление host-маршрута до IP-адреса целевого прокси-сервера через физический шлюз (предотвращение зацикливания трафика).
     - Назначение IP-адреса виртуальному интерфейсу Wintun (например, `10.0.85.2/32`, peer `10.0.85.1`).
     - Добавление перекрывающих маршрутов по умолчанию: `0.0.0.0/1` и `128.0.0.0/1` через Wintun-интерфейс (метрика 1).
     - Конфигурация DNS на интерфейсе Wintun (например, `10.0.85.1` или настроенные upstream DNS) через Win32 `SetInterfaceDnsSettings`.
3. **Безопасная очистка маршрутов**:
   - При корректном завершении процесса, по сигналу Ctrl+C или аварийном падении:
     - Удаление host-маршрута к серверу.
     - Удаление маршрутов `0.0.0.0/1` и `128.0.0.0/1`.
     - Уничтожение сессии и адаптера Wintun.
   - При старте `outline-ws-rust.exe` выполняется предполётная очистка возможных оставшихся маршрутов от предыдущего аварийного завершения.

### 3.3. GUI-клиент (`bins/outline-windows`)

1. **Стек**:
   - Tauri v2 (Rust backend, WebView2 frontend).
   - Фронтенд: Svelte 5 / Vite / Tailwind CSS.
2. **Системный трей**:
   - Постоянная иконка в трее Windows (щит: серый — не активен, зелёный — подключен, жёлтый — в процессе подключения или ошибка).
   - Контекстное меню по правому клику:
     - Статус: `Подключено` / `Отключено` / `Ошибка`.
     - Кнопка: `Подключить` / `Отключить`.
     - Список серверов (быстрое переключение с галочкой на активном).
     - Режим работы: `SOCKS5 (Системный прокси)` или `TUN (Полный VPN)`.
     - Переключатель `Только TCP` (выключение HTTP/3 носителей).
     - Разделитель.
     - Пункты: `Серверы...`, `Настройки...`, `Журнал...`.
     - `Выход`.
   - По левому клику: открытие/фокусировка главного окна серверов.
3. **Экраны приложения**:
   - **Главное окно («Серверы»)**:
     - Карточки серверов: имя, протокол (`VLESS`, `SS`), адрес, активный носитель (`xhttp`, `ws`, `h3`), пинг.
     - Добавление профилей: кнопка добавления, автоматическое распознавание ссылок из буфера обмена (`vless://`, `ss://`, `outline://`).
     - Подписки: добавление URL подписки (`https://`), ручное и периодическое автообновление, количество серверов в подписке.
     - Удаление и редактирование профилей.
   - **Окно «Настройки»**:
     - Выбор режима работы по умолчанию (`SOCKS5` / `TUN`).
     - Переключатель «Только TCP» (без HTTP/3).
     - Чекбокс «Запускать при старте Windows» (запись в реестр `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`).
     - Проверка обновлений (сверка версий с GitHub Releases).
   - **Окно «Журнал»**:
     - Текстовая область с виртуальным скроллингом, отображающая live stdout/stderr из `outline-ws-rust.exe`.
     - Кнопка «Копировать всё», очистка, фильтр по уровню (`INFO`, `WARN`, `ERROR`).
4. **Управление системным прокси в режиме SOCKS5**:
   - Модуль `SystemProxyManager`:
     - Включение: запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`:
       `ProxyEnable = 1`, `ProxyServer = "socks=127.0.0.1:1080"`.
     - Оповещение подсистемы WinINet: вызов `InternetSetOptionW(NULL, INTERNET_OPTION_SETTINGS_CHANGED, NULL, 0)` и `InternetSetOptionW(NULL, INTERNET_OPTION_REFRESH, NULL, 0)`.
     - Выключение: `ProxyEnable = 0`, повторный вызов `InternetSetOptionW`.
     - Снятие прокси при закрытии приложения или аварийном завершении.
5. **Управление привилегиями (UAC)**:
   - В режиме SOCKS5 приложение и ядро работают без прав администратора.
   - В режиме TUN: вызов `outline-ws-rust.exe` осуществляется через Win32 `ShellExecuteExW` с глаголом `runas`, что вызывает стандартный диалог контроля учетных записей (UAC) только для фонового сетевого процесса, оставляя интерфейс Tauri в обычном непривилегированном режиме пользователя.

## 4. Сборка, упаковка и развертывание

### 4.1. Кросс-компиляция с macOS
* Инструмент: `cargo-xwin` (устанавливается через `cargo install cargo-xwin`).
* Целевой таргет: `x86_64-pc-windows-msvc`.
* Бандл артефактов (`scripts/package-windows.sh`):
  1. `outline-ws-rust.exe` (релизная сборка ядра).
  2. `wintun.dll` (официальный подписанный драйвер для x64).
  3. `OutlineProxy.exe` (Tauri-приложение).
  4. Формирование переносимого zip-архива и NSIS-инсталлятора (`.exe`).

### 4.2. Тестирование и верификация на `.105`
* ВМ Windows 10/11 x86_64 на NAS `.105`.
* Доставка сборки: через SMB-шару NAS `\\192.168.1.105\...` или по SCP.
* План проверки:
  1. Запуск `OutlineProxy.exe`, проверка появления иконки в трее.
  2. Добавление тестового VLESS / SS ключа.
  3. Проверка SOCKS5-режима: включение, проверка браузером (Edge/Chrome), проверка смены IP.
  4. Проверка TUN-режима: запрос UAC, поднятие адаптера Wintun, проверка работы консольных утилит (`ping`, `curl`) и DNS без утечек.
  5. Переключение в режим «Только TCP» — проверка переподключения и блокировки H3.
  6. Завершение работы: проверка снятия системного прокси и очистки таблицы маршрутизации.

## 5. Границы реализации и инварианты

1. **Не изменять серверную логику (`bins/outline-ss-rust`)**: все изменения затрагивают клиентскую часть (`bins/outline-ws-rust`, `crates/outline-tun`, `bins/outline-windows`).
2. **Сохранение существующего поведения на Linux, macOS и Android**: все новые платформенные ветвления строго изолируются директивами `#[cfg(windows)]` и `#[cfg(not(windows))]`.
3. **CI-гейт**: добавление шага проверки компиляции под Windows (`cargo check -p outline-ws-rust --target x86_64-pc-windows-msvc`) в GitHub Actions.
