# Memory-тюнинг

Источник истины для per-node cgroup-лимитов памяти `outline-ws-rust` и
`outline-ss-rust`: [`fleet.tsv`](fleet.tsv) декларирует лимиты,
[`apply.sh`](apply.sh) приводит узлы к таблице.

Реальные имена узлов, домены и адреса парка в этом документе заменены условными: `198.51.100.0/24` — домашняя сеть (`.102`, `.104` и т. д. — последний октет). Соответствие — в локальном некоммитируемом `FLEET.local.md`.

До 2026-08-24 эти лимиты ставились на каждом узле руками, в репозитории не жили,
терялись при переустановке ОС и несли мёртвые под jemalloc переменные
`MIMALLOC_*`.

## Формат таблицы

Одна строка на узел в `fleet.tsv`, столбцы разделены табуляцией или пробелами;
строки с `#` — комментарии:

```
short   ssh_target                   ws_high  ws_max  ss_high  ss_max
.104    mmv@198.51.100.104             600M     700M    130M     150M
```

| Столбец | Кто читает | Смысл |
|---|---|---|
| `short` | `install.sh --host` (провижининг), `apply.sh <host>` | короткое имя узла |
| `ssh_target` | `apply.sh` | ssh-цель, на которую раскатываются лимиты; тоже принимается как `apply.sh <host>` |
| `ws_high` / `ws_max` | оба | `MemoryHigh` / `MemoryMax` для `outline-ws-rust` |
| `ss_high` / `ss_max` | оба | `MemoryHigh` / `MemoryMax` для `outline-ss-rust` |

- Дефис (`-`) — сервиса на узле нет, его drop-in не трогается.
- У каждого лимита мягкая ступень reclaim: `High < Max`. Ниже `High` ничего не
  происходит; между `High` и `Max` ядро вытесняет страницы и притормаживает
  сервис; на `Max` — OOM-kill. `High = Max` (прежнее состояние) означало
  отсутствие ступени — сразу kill.
- `Max` держится ниже `MemAvailable` узла. С лимитом выше доступной памяти узел
  уйдёт в zram-своп и системный OOM раньше, чем cgroup досчитает до лимита.
  Замеренный запас по узлам — в спеке (см. [Спека](#спека)).
- `apply.sh` сравнивает живой RSS с `High`, считая суффикс `M`
  (`high_mib=${high%M}`); значения `High` задавайте в `M`.

## Раскатка

Запускается с машины разработчика; скрипт сам переходит в свой каталог и
ходит на узлы по ssh через `sudo bash`:

```bash
./apply.sh --dry-run          # показать, что изменится на каждом узле
./apply.sh                    # применить на все узлы
./apply.sh mmv@198.51.100.104   # один узел (ssh-цель или короткое имя)
```

Для каждого сервиса с лимитом в таблице `apply.sh` пишет один drop-in
`/etc/systemd/system/<unit>.service.d/20-memory.conf` (`MemoryAccounting=yes`,
`MemoryHigh`, `MemoryMax`), делает `systemctl daemon-reload` и применяет лимиты
к живому сервису без рестарта (`systemctl set-property --runtime`). Плюс:

- удаляет `30-mem-tuning.conf` (мёртвые `MIMALLOC_*`);
- удаляет остатки `*.pre-*` / `*.bak.*` в каталоге drop-in;
- удаляет `/etc/systemd/system.control/<unit>.service.d`, оставленный ручным
  `set-property` (он персистентный и приоритетнее — иначе после ребута
  переопределит таблицу);
- пишет `THREAD_STACK_SIZE_KB=512` для `outline-ws-rust` отдельным
  `30-thread-stack.conf`.

Лимиты применяются вживую. Env-переменная стека вступит только при следующем
рестарте, но её значение здесь не меняется, так что рестарт не нужен.

`apply.sh` откажется применять лимит к сервису, у которого живой
`MemoryCurrent` уже не ниже нового `High`, и напечатает `REFUSE <unit>: current
…MiB >= new High …MiB` — применение сразу запустило бы reclaim. Сначала поднимите
лимит или разберитесь с процессом. Узел, уже совпадающий с таблицей, печатает
`ok <unit>: already matches`.

## Провижининг с нуля

Переустановленный узел поднимается уже с лимитами:
`collect-from-reference.sh` кладёт `fleet.tsv` в бандл
(`<bundle>/memory-tuning/fleet.tsv`), а фаза `services` в `install.sh` находит
строку узла по `--host` (сравнивает со столбцом `short`) и пишет тот же
`20-memory.conf` (и `30-thread-stack.conf` для клиента) до того, как включает и
запускает юниты. `set-property` не нужен: systemd читает drop-in при старте
юнита.

Узел, которого нет в `fleet.tsv`, остаётся с дефолтами systemd, а `install.sh`
предупреждает `memory-tuning: --host '<host>' not in fleet.tsv`. Сервис с `-` в
своей строке остаётся с дефолтами без предупреждения. Бандл без
`memory-tuning/fleet.tsv` (снятый до появления таблицы) пропускается с
сообщением.

После первого провижининга правки таблицы доносятся до живых узлов через
`apply.sh`; перезапускать провижинер ради смены лимита не нужно.
