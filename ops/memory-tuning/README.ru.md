# Memory-тюнинг

Источник истины для per-node cgroup-лимитов памяти `outline-ws-rust` и
`outline-ss-rust`.

До 2026-08-24 эти лимиты ставились на каждом узле руками, в репозитории не жили,
терялись при переустановке ОС и несли мёртвые под jemalloc переменные
`MIMALLOC_*`. Этот каталог заменяет тот подход: [`fleet.tsv`](fleet.tsv)
декларирует лимиты, [`apply.sh`](apply.sh) приводит узлы к таблице.

## Таблица

Одна строка на узел в `fleet.tsv`, разделитель — табуляция:

```
host   ws_high  ws_max  ss_high  ss_max
```

- Дефис (`-`) — сервиса на узле нет, его drop-in не трогается.
- У каждого лимита мягкая ступень reclaim: `High < Max`. Ниже `High` ничего не
  происходит; между `High` и `Max` ядро вытесняет страницы и притормаживает
  сервис; на `Max` — OOM-kill. `High = Max` (прежнее состояние) означало
  отсутствие ступени — сразу kill.
- **`Max` держится ниже `MemAvailable` узла.** Лимит выше доступной памяти —
  фиктивный предохранитель: узел уйдёт в zram-своп и системный OOM раньше, чем
  cgroup досчитает до него. Замеренный запас по узлам — в спеке.

## Раскатка

```bash
./apply.sh --dry-run          # показать, что изменится на каждом узле
./apply.sh                    # применить на все узлы
./apply.sh mmv@198.18.1.104   # один узел
```

Для каждого сервиса `apply.sh` пишет один canonical drop-in
`/etc/systemd/system/<unit>.service.d/20-memory.conf` и применяет лимиты к
живому сервису **без рестарта** (`set-property --runtime`). Плюс:

- удаляет `30-mem-tuning.conf` (мёртвые `MIMALLOC_*`);
- удаляет любой `/etc/systemd/system.control/<unit>.d`, оставленный ручным
  `set-property` (он персистентный и приоритетнее — иначе после ребута
  переопределит таблицу);
- пишет `THREAD_STACK_SIZE_KB=512` для клиентов отдельным `30-thread-stack.conf`.

Лимиты применяются вживую. Env-переменная стека вступит только при следующем
рестарте, но её значение здесь не меняется, так что рестарт не нужен.

`apply.sh` откажется применять лимит к сервису, у которого живой RSS уже выше
нового `High` (это вызвало бы немедленный reclaim-шторм) — сначала поднять лимит
или разобраться с процессом.

## При провижининге с нуля

Переустановленный узел поднимается уже тюнингованным: `collect-from-reference`
кладёт `fleet.tsv` в бандл (`bundle/memory-tuning/fleet.tsv`), а `install.sh`
находит строку узла по `--host` и пишет тот же `20-memory.conf` до старта
сервисов. Живёт и на живом узле — `set-property` при провижининге не нужен,
systemd читает drop-in при первом старте юнита.

Узел, которого нет в `fleet.tsv` (или сервис с `-` в его строке), остаётся с
дефолтами systemd — так же, как до правки. Бандл без `memory-tuning/fleet.tsv`
(старый) пропускается с подсказкой.

После первого провижининга `apply.sh` — то, чем правки таблицы отражаются на
живых узлах: полный прогон провижинера ради смены лимита — перебор.
