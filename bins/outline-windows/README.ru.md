# Outline Proxy — клиент для Windows

English version: [README.md](README.md).

Нативный клиент для Windows 10/11 (x86_64) на базе фреймворка Tauri v2 и Svelte 5.
Работает поверх высокопроизводительного сетевого ядра `outline-client` (VLESS,
Shadowsocks AEAD, WebSocket, HTTP/3, padding, failover): приложение запускает
ядро дочерним процессом и управляет системным прокси, профилями, подписками и
маршрутизацией.

Интерфейс приложения на русском языке; все надписи и диалоги оптимизированы
для нативного взаимодействия в окружении Windows.

## Архитектура

Приложение спроектировано в виде модульной системы:

- **GUI-оболочка (Frontend)**: Svelte 5 (Runes), TypeScript, Tailwind CSS, Vite.
  Компактное окно с адаптивной светлой и тёмной темами, карточками управления
  туннелем, списком профилей серверов, журналом событий и модальными диалогами
  настроек.
- **Бэкенд приложения (Tauri v2 + Rust Edition 2024)**:
  - `process_controller.rs` — запуск, мониторинг состояния и штатное завершение
    сетевого ядра `outline-client.exe`.
  - `profile_store.rs` — безопасное хранение профилей серверов, настроек и
    подписок в локальном каталоге `%APPDATA%\su.beerloga.outline.windows`
    (JSON-манифест).
  - `traffic_monitor.rs` — опрос встроенного control API ядра `outline-client`
    для отображения скорости (downlink/uplink) и объема трафика в реальном
    времени.
  - `tray.rs` — системный трей Windows (значок в панели задач, всплывающее меню
    быстрого подключения, переключения профилей, режимов и выхода).
  - `updater.rs` / `version.rs` — подсистема проверки и безопасной установки
    обновлений с верификацией контрольных сумм.
- **Сетевое ядро (`outline-client.exe`)**: скомпилированный бинарник единого
  клиентского ядра mono-repo `outline-proxy`.
- **Режимы работы**:
  - **SOCKS5 (системный прокси)**: ядро слушает порт `127.0.0.1:1080`,
    приложение переключает системный прокси Windows через вызовы WinInet API и
    реестр Windows (`HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`:
    `ProxyEnable = 1`, `ProxyServer = 127.0.0.1:1080`). Не требует прав администратора.
  - **TUN (полный L3 VPN)**: создание виртуального сетевого адаптера через
    официальный высокопроизводительный драйвер **Wintun** (`wintun.dll`).
    Приложение настраивает сетевые маршруты через Windows IP Helper API
    (`windows-sys` Win32_NetworkManagement_IpHelper) — точечные host-маршруты до
    серверов через физический шлюз (во избежание петель маршрутизации) и
    дефолтный маршрут `0.0.0.0/0` через интерфейс Wintun. Перехватывает весь
    системный сетевой трафик, включая службы Windows, консольные утилиты и DNS.
    Включает защиту от утечек IPv6. Требует запуска с правами администратора.

## Проверка обновлений и автообновление

Клиент оснащён встроенным механизмом проверки и установки обновлений без
необходимости внешних инсталляторов.

### Интерактивный футер с версией
В нижней части главного окна расположен интерактивный элемент с текущей версией:
- **Nightly-сборки**: `nightly · v1.9.2 (971282b6)` (канал, версия и короткий SHA коммита).
- **Release-сборки**: `v1.9.2`.

При клике на футер инициируется интерактивная проверка обновлений:
1. Текст футера переключается на `проверка обновлений…`.
2. Если установлена последняя версия, на 4 секунды отображается `актуальная версия`,
   после чего футер возвращается к номеру версии.
3. Если найдено обновление, отображается статус `доступно <label>` и автоматически
   открывается модальное окно `UpdateModal`.

### Фоновая тихая проверка
Через 5 секунд после каждого старта приложения в фоне выполняется тихий опрос
новых версий. При обнаружении обновления статус футера меняется на
`доступно <label> — нажмите`, не блокируя интерфейс и не отвлекая пользователя
модальными окнами.

### Каналы обновлений
Канал сборки фиксируется при компиляции через переменную окружения `OUTLINE_BUILD_CHANNEL`:
- **`nightly`** (по умолчанию): проверяет релиз по тегу `windows-nightly` в
  GitHub API (`https://api.github.com/repos/balookrd/outline-proxy/releases/tags/windows-nightly`).
  Сверяет хэш коммита артефакта `OutlineProxy-x86_64-<commit>.zip` с хэшем запущенного
  бинарника (с поддержкой префиксного сопоставления и отсечением суффикса `-dirty`).
- **`release`**: запрашивает `/releases/latest` в GitHub API
  (`https://api.github.com/repos/balookrd/outline-proxy/releases/latest`), проверяет
  единый CalVer-тег `v*` и скачивает целевой архив `OutlineProxy-v<ver>-Windows-x86_64.zip`.

### Сверка контрольной суммы по `SHA256SUMS.txt`
Для защиты от повреждения данных или подмены файлов перед установкой выполняется
строгая проверка целостности:
1. Приложение загружает файл `SHA256SUMS.txt` из ассетов найденного релиза.
2. Скачивание zip-архива обновления производится потоково чанками (`reqwest`) с
   расчётом дайджеста SHA-256 на лету через криптографическую библиотеку `ring`
   (`ring::digest::SHA256`).
3. В процессе загрузки модальное окно `UpdateModal` отображает точный прогресс-бар в
   процентах.
4. После завершения скачивания вычисленный SHA-256 хеш сверяется с записью в
   манифесте. При любом несоответствии временный архив немедленно удаляется с
   диска, а процесс обновления прерывается с ошибкой.

### Безопасная распаковка без zip-slip
Архив распаковывается во временный каталог staging в директории `%TEMP%`.
Каждый файл проверяется через `zip_file.enclosed_name()` — любые записи,
содержащие относительные пути вида `../` или абсолютные пути, немедленно
отклоняются, что полностью предотвращает уязвимость Directory Traversal (Zip Slip).

### Бесшовная замена файлов (`apply_update.cmd`) и автореконнект
Так как исполняемый файл запущенного приложения заблокирован операционной системой
Windows для записи, замена файлов происходит через отсоединённый скрипт:
1. **Флаг автореконнекта**: если туннель активен, в `profile_store` выставляется
   флаг `settings.reconnect_after_update = true`, после чего сетевое ядро
   останавливается.
2. **Скрипт обновления**: формируется временный батник `outline_update_<pid>.cmd`,
   запускаемый как полностью фоновый процесс без создания окна (`CREATE_NO_WINDOW | DETACHED_PROCESS`):
   - Ожидает в цикле через `tasklist` полного завершения процесса приложения по его PID.
   - Копирует файлы из staging-каталога в рабочую папку приложения (`xcopy /Y /Q /E`).
   - Запускает обновленный `OutlineProxy.exe`.
   - Очищает staging-каталог и самоудаляется (`del "%~f0"`).
3. **Автоматическое переподключение**: новый экземпляр `OutlineProxy.exe` при старте
   обнаруживает `reconnect_after_update`, сбрасывает флаг в `false`, сохраняет
   настройки и через 1 секунду автоматически поднимает туннель к последнему
   активному профилю.

## Сборка и упаковка

Сборка Windows-клиента автоматизирована скриптом `scripts/package-windows.sh`.

### Требования к окружению
- **Rust**: тулчейн `nightly` или `stable` с поддержкой таргет-платформы `x86_64-pc-windows-msvc`.
- **Node.js**: Node 20+, пакетный менеджер `pnpm`.
- **Инструменты кросс-компиляции** (при сборке на macOS / Linux):
  - `cargo-xwin` (`cargo install cargo-xwin`).
  - LLVM и LLD (`brew install llvm lld` на macOS).

### Команды сборки

Проверка окружения и необходимых зависимостей без запуска компиляции:
```bash
./scripts/package-windows.sh --check-only
```

Полная сборка релизного пакета:
```bash
./scripts/package-windows.sh
```

Сборка только сетевого ядра (`outline-client.exe`) и драйвера Wintun (без GUI):
```bash
./scripts/package-windows.sh --skip-ui
```

Скрипт выполняет:
1. Сборку frontend-ассетов через `pnpm build` (`bins/outline-windows/dist`).
2. Компиляцию сетевого ядра `outline-client` под `x86_64-pc-windows-msvc`.
3. Компиляцию оболочки `outline-windows` под `x86_64-pc-windows-msvc`.
4. Загрузку и верификацию официального драйвера Wintun `0.14.1` по эталонному SHA-256.
5. Формирование архива `OutlineProxy-x86_64.zip` и контрольных сумм `SHA256SUMS.txt` в каталоге `dist/windows/`.
